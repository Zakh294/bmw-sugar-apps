# DeX Drive — Samsung DeX на центральному екрані BMW iDrive 7

*English: [README.en.md](README.en.md)*

> **Тестова версія 0.1.0.** Зібрана й перевірена на ПК (фейковий телефон, фейковий рендерер, фейковий декодер).
> На машині ще не запускалась: див. [Що перевірено, а що ні](#що-перевірено-а-що-ні).
> **Лише на стоянці.** Неофіційно, не пов'язано з BMW чи Samsung, на власний ризик ([LEGAL.md](../../LEGAL.md)).

Телефон Samsung з **One UI 8 (Android 16)** підключається до головного блока кабелем USB або по Wi‑Fi, і його
**DeX** (робочий стіл з вікнами, панеллю завдань, клавіатурою) відкривається на весь центральний екран. Екран
сенсорний: пальці (кілька одночасно) працюють як на планшеті, а контролер iDrive — як ноутбук (тачпад, клік, стрілки). Відео декодує GPU
головного блока, тож телефон не мусить дзеркалити свій власний екран — DeX іде на окремий віртуальний дисплей.

## Як це влаштовано

```
Телефон (One UI 8)                         Головний блок MGU (iDrive 7)
┌────────────────────────┐   USB / Wi‑Fi   ┌─────────────────────────────────────────────┐
│ scrcpy-server 5.0.1    │◄── ADB ────────►│ dex-drive-d (сервіс, root)                  │
│  • віртуальний дисплей │   H.264 відео   │  • ADB: usbfs або TCP 5555, свій ключ RSA   │
│    1832×720 → DeX      │────────────────►│  • dexdec: GPU (Intel Media SDK) → I420     │
│  • дотики, прокрутка   │◄── керування ───│    → /dev/shm/mgu-video-dexdrive            │
└────────────────────────┘                 │ DeX Drive (додаток)                         │
                                           │  • mgu-render: шар з відео, дотики, knob     │
                                           └─────────────────────────────────────────────┘
```

- **scrcpy-server** (Genymobile, Apache‑2.0) запускається на телефоні через ADB без root і створює новий
  віртуальний дисплей. One UI 8 показує на ньому DeX — той самий механізм, що й `scrcpy --new-display`.
- **dex-drive-d** — сервіс на блоці (Go, статичний): ADB‑хост без libusb (бере в телефона лише інтерфейс ADB,
  MTP/медіа лишаються машині), копіює сервер на телефон, читає відео й передає дотики.
- **dexdec** — апаратний декодер H.264 на GPU блока (Intel HD 505, Media SDK), на основі ytdec з RideTube і
  waze-on-cluster. Пише кадри у відеофайл mgu-render.
- **DeX Drive** — сторінка в меню iDrive і шар над екраном через mgu-render (той самий рендерер, що в RideTube).

## Що потрібно

- Головний блок iDrive 7 з root, MGU Store і **mgu-render 0.6.11+** (його ставить Store; RideTube вже його має).
- Для контролера iDrive — **Controller gate** (`mgu-inputgate`, джерело `cauliflowermossgrape/idrive7-apps`, у Store
  в «Системних утилітах»). Store ставить його разом із DeX Drive; після нього — перезапуск блока.
- Телефон Samsung з **One UI 8 або новішою** (Android 16). На старших One UI DeX не вміє працювати на
  віртуальному дисплеї — сервіс так і скаже.
- На телефоні **Параметри розробника → Налагодження по USB** (увімкнути).
- Для Wi‑Fi: ADB на порту 5555 (див. нижче). Для USB нічого більше не треба.

## Встановлення

1. Store → Settings → Sources: джерело `Zakh294/bmw-sugar-apps`, Channel **`main`** (як для SpeedCam) → Check now.
2. Store → **DeX Drive** → Install. Store сам поставить **DeX Drive service** (`dex-drive-d`), mgu-render і Controller gate.
3. **Перезапусти головний блок** (Settings → Restart head unit): новий сервіс стартує лише після перезапуску
   (так працює recmgr блока). Store до того покаже його як *restart pending*.

## Перше підключення (USB)

1. Підключи телефон кабелем у USB‑порт з даними (той, що для CarPlay / Android Auto / музики).
2. Відкрий **DeX Drive** у меню додатків → **Відкрити DeX на екрані**.
3. На телефоні з'явиться «Дозволити налагодження по USB?» з відбитком ключа «BMW-iDrive@dex-drive» →
   постав **«Завжди дозволяти з цього комп'ютера»** → **Дозволити**. Більше питати не буде.
4. Телефон може спитати, як показувати другий екран — вибери **DeX**.
5. Через кілька секунд DeX займе екран. Унизу ліворуч — кнопка з чотирма квадратиками: назад до сторінки
   DeX Drive (налаштування, «Зупинити»). Стрілка «назад» iDrive ліворуч угорі виходить, як з будь-якого додатка.

Наступного разу: підключив → відкрив DeX Drive → DeX одразу на екрані (якщо сесія ще жива — миттєво).

## Wi‑Fi (без кабелю)

Сервіс шукає телефон на порту **5555** серед пристроїв, яких бачить блок (телефон у хотспоті машини
`DIRECT-BMW`, або блок у хотспоті телефона через mgu-uplink). Порт 5555 вмикається:

- **машиною (найпростіше):** з налаштуванням «USB або Wi‑Fi» під'єднай телефон кабелем хоч раз після його
  увімкнення. Сервіс сам відкриє на ньому порт 5555 (як `adb tcpip 5555`; USB на кілька секунд перепідключиться,
  на сторінці буде «Вмикаю на телефоні ADB по Wi‑Fi…»). Далі до перезавантаження телефона кабель не потрібен;
- з ПК: `adb tcpip 5555` (телефон по USB), або
- на самому телефоні: Termux (`pkg install android-tools`) чи LADB через «Бездротове налагодження».

Поки телефон на кабелі, сервіс запам'ятовує його Wi‑Fi-адресу й потім шукає його там, а як ні — перебирає всю
свою Wi‑Fi-мережу на порту 5555. Телефон і машина мають бути в одній мережі: телефон у хотспоті машини, машина в
хотспоті телефона або обидва в одному Wi‑Fi.

Після перезавантаження телефона порт 5555 знову закритий — це обмеження Android. «Бездротове налагодження»
Android 11+ (з кодом спарювання, TLS) сервіс поки не підтримує. Якщо телефон має стабільну адресу, її можна
вписати в `/var/opt/dex-drive-data/phone-ip` (по SSH; один рядок `IP` або `IP:порт`).

Для Wi‑Fi в налаштуваннях краще «Якість відео: 4 Мбіт/с».

## Налаштування

| Налаштування | Що робить |
|---|---|
| Мова / Language | Українська або English |
| Підключення телефона | USB або Wi‑Fi (ADB 5555) / лише USB |
| Масштаб DeX | щільність віртуального дисплея: 120–240 dpi, менше = більше вміщається, дрібніше |
| Кадрів на секунду | 30 або 60 |
| Якість відео | 4 / 8 / 16 Мбіт/с |
| Лише на стоянці | увімкнено: у русі (понад 3 км/год) DeX ховається, сесія живе далі |
| Контролер iDrive керує DeX | коліщатко, натискання й нахили — для DeX, поки він на екрані (див. нижче) |
| Тачпад контролера — вказівник DeX | тачпад на коліщатку працює як тачпад ноутбука |
| Гасити екран телефона | після старту гасить власний екран телефона (DeX працює далі); кнопка живлення вмикає |

Зміна масштабу, кадрів, якості чи підключення перезапускає DeX з новими параметрами.

## Контролер iDrive

Поки DeX на екрані, контролер працює для нього (кнопки MENU / BACK і стрілка «назад» на екрані виходять, як завжди):

| Дія | У DeX |
|---|---|
| Палець по тачпаду | рухає вказівник DeX (швидше рух — далі) |
| Короткий тап по тачпаду | клік лівою |
| Тап двома пальцями | правий клік (контекстне меню) |
| Два пальці вгору / вниз | прокрутка (вміст іде за пальцями) |
| Поворот коліщатка | прокрутка там, де вказівник |
| Натискання коліщатка | клік там, де вказівник; утримання — довге натискання, з пальцем по тачпаду — перетягування |
| Нахил ↑ ↓ ← → | клавіші-стрілки |

Вказівник стає туди, де ти востаннє торкнувся екрана; стрілку малює DeX Drive (Android для такого вказівника курсора
не показує). Без Controller gate (наприклад, коли його тримає GPU renderer) коліщатко читається із сигналу авто, і
меню iDrive під картинкою теж його чує: кнопки сторінки, поки DeX на екрані, тоді не спрацьовують. Тачпад працює лише в «режимі дотику» контролера: DeX
Drive вмикає його, поки DeX на екрані, і вимикає після (так само робить екран рукописного вводу iDrive).

## Що перевірено, а що ні

**Перевірено на ПК** (`native/dex_drive/dexd`: `go test`, `test/dex_drive/*.js`):
- ADB: рукостискання, ключ (формат Android і підпис перевіряє фейковий adbd так само, як справжній), запит дозволу,
  повторне підключення без запиту, `push` через sync, shell, потоки з керуванням потоком;
- протокол scrcpy 5.0.1: аргументи сервера, сокети відео й керування, заголовки, повідомлення дотиків, клавіш,
  прокрутки — побайтово за вихідним кодом сервера;
- відео до файла MGVF через фейковий декодер (той самий `main.cpp`, без GPU);
- додаток у заглушці головного блока проти фейкового mgu-render: розміщення шару, відео, дотики з кількома
  пальцями, кнопка меню, утримання коліщатка;
- `dexdec` зібрано під блок (x86‑64, glibc 2.27, `/lib/ld-linux-x86-64.so.2`), усі імпорти Media SDK / VA є в
  бібліотеках блока (за списками символів з RideTube).

**Лише в машині** (що може не спрацювати з першого разу):
- USB через usbfs на блоці (чи не тримає телефон інший процес; автомобільний Android Auto по кабелю);
- апаратне декодування живого потоку телефона (`dexdec`, порядок декодування — найменша затримка);
- чи One UI сам вмикає DeX на віртуальному дисплеї, чи питає;
- прозорість лівої колонки (стрілка «назад» iDrive над нашим шаром), напрям коліщатка;
- тачпад контролера (режим дотику, напрям і швидкість вказівника) — значення сигналів узято з вимірів у машині
  інших авторів, на нашому G01 ще не перевірено.

## Якщо щось не так

Логи на блоці (по SSH):

```sh
journalctl -u dex-drive-d -n 100          # сервіс
cat /var/opt/dex-drive-data/dexd.log      # сервіс: підключення, телефон, сесія
cat /var/opt/dex-drive-data/dexdec.log    # декодер
journalctl -u mgu-render -n 50            # рендерер (чи взяв відео, чи показує шар)
```

| Сторінка каже | Що робити |
|---|---|
| Сервіс dex-drive-d не запущено | встанови «DeX Drive service» і перезапусти блок |
| Шукаю телефон на USB… | увімкни «Налагодження по USB»; спробуй інший кабель / порт з даними |
| На телефоні натисни «Дозволити» | розблокуй телефон, підтверди; «Забути ключ ADB» — щоб спитало знову |
| … needs One UI 8 (Android 16) | телефон на старшій прошивці: DeX на віртуальному дисплеї неможливий |
| the hardware decoder did not start | надішли `dexdec.log` — це місце, яке на ПК не перевірити |
| Немає mgu-render / не показує відео | встанови або онови mgu-render (0.6.11+) |

## Видалення

Store → Installed → DeX Drive → Remove, потім DeX Drive service → Remove. Ключ ADB блока лишається в
`/var/opt/dex-drive-data` (видали теку, якщо треба); на телефоні: Параметри розробника → «Відкликати дозволи
налагодження по USB».
